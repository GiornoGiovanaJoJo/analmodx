# План работ (минимальное качественное улучшение)

## Цель
Обеспечить минимальное, но подтверждаемое улучшение качества сайта без обещания резкого роста метрик.

## Регламент работ на действующем сайте
- Работы по возможности выполнять вне пикового трафика или короткими итерациями с проверкой сайта после каждого шага.
- Перед каждым существенным изменением делать бэкап БД и файлов.
- Критические действия с возможным простоем проводить только по предварительному согласованию времени с Заказчиком.
- До старта зафиксировать текущие версии `robots.txt` и `sitemap.xml`.

## Чеклист внедрения (ТЗ)
- Обновить уязвимый `login extra` до версии с исправлениями.
- Ввести единую URL-политику на уровне `nginx/MODX`:
  - схлопывание `//` в `/`;
  - `301` с `index.php?q=*` на канонический clean URL;
  - единая политика trailing slash;
  - обработка query URL: `301` на канонический или `canonical + noindex` для допустимых.
- Привести в порядок `robots.txt` (убрать дубли, упростить правила query, синхронизировать группы UA).
- Выполнить фронтенд-чистку:
  - добавить `defer` для блокирующих скриптов;
  - вынести inline JS/CSS в версионированные ассеты;
  - удалить неиспользуемые legacy JS-плагины, объединить активные.
- Снизить `CLS` через фиксацию размеров ключевых изображений (`width/height`).
- Исправить технические дефекты шаблонов (`<spam>` -> `<span>`, пробелы в `href`).
- Проверить/включить `DB cache` в MODX и тест очистки/инвалидации.
- Проверить кеширование статики (`Cache-Control` для версионированных CSS/JS).
- Нормализовать работу с изображениями:
  - `loading="lazy"` и `decoding="async"` где уместно;
  - для LCP-изображения: `preload`/`fetchpriority=high`, контроль размеров/форматов.
- Унифицировать микроразметку (предпочтительно `JSON-LD`) и валидировать ключевые шаблоны.
- Актуализировать `sitemap` (покрытие, `lastmod`, удаление нерелевантных URL по списку администратора).
- Снизить 404-шум в Метрике по паттернам (`?q=`, `//`, parameter junk).

## KPI (усиленные и реалистичные)
Проверка по данным `PageSpeed/Lighthouse` (до/после), с акцентом на подтверждаемое улучшение.

- Performance Score: мобильные `>= 65-70`, ПК `>= 92`.
- FCP: мобильные `<= 1.8s`, ПК `<= 0.7s`.
- LCP: мобильные `<= 4.8s`, ПК `<= 1.8s`.
- TBT: мобильные `0s` (сохранить текущий уровень), ПК `<= 100ms`.
- CLS: мобильные `<= 0.25`, ПК `<= 0.08`.
- Speed Index: мобильные `<= 3.8s`, ПК `<= 1.8s`.

## Дополнительные минимумы качества
- INP: мобильные `<= 250ms`, ПК `<= 200ms`.
- TTFB: мобильные `<= 0.9s`, ПК `<= 0.6s`.
- Размер передаваемой страницы (главная): мобильные `<= 2.5MB`, ПК `<= 2.0MB`.
- Количество HTTP-запросов (главная): мобильные `<= 95`, ПК `<= 70`.
- Доля 4xx/5xx при обходе ключевых URL: `<= 1%`.

## Приемка и подтверждение
- Подтверждение улучшений: отчет `PageSpeed/Lighthouse` до/после + перечень внедренных изменений.
- Показатели фиксируются на момент сдачи и периода сопровождения.
- После завершения сопровождения метрики могут меняться из-за внешних факторов (контент, хостинг, CMS, сторонние сервисы).

## Границы ответственности
- Исполнитель отвечает только за изменения в пределах утвержденного ТЗ и приложений.
- Изменения вне ТЗ оформляются и оплачиваются отдельно.
- Исполнитель не отвечает за сбои из-за действий третьих лиц и изменений после сдачи.
