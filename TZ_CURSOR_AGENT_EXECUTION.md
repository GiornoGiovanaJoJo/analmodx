# Техническое задание для агента Cursor

## 1) Контекст и цель

Цель: выполнить согласованный пакет технических работ по сайту `m-trud.ru` (MODX + nginx) с акцентом на подтверждаемое улучшение качества и производительности, без рискованных изменений в рабочее время.

Основание: материалы проекта в этом репозитории (аудит, договор, приложения, извлеченные данные, скрипты проверок).

## 3) Ограничения и правила выполнения

- Работать итерациями: одно изменение -> проверка сайта -> фиксация результата.
- По возможности выполнять изменения вне пикового трафика.
- Перед каждым существенным изменением: бэкап БД и файлов.
- Критические действия с потенциальным простоем только после согласования времени.
- Не менять объем работ за рамками данного ТЗ без отдельного согласования.

## 4) Приоритеты работ

## P0 — критично (безопасность и URL-нормализация)

1. Обновить уязвимый `Login Extra` до безопасной версии.
2. Нормализовать URL на уровне `nginx/MODX`:
   - схлопывание `//` в `/`;
   - корректный `301` с `index.php?q=*` на канонический URL;
   - единая политика trailing slash.
3. Зафиксировать каноникал-политику для параметрических URL:
   - либо `301` на канонический URL;
   - либо `canonical + noindex` для разрешенных страниц с параметрами.
4. Проверить и скорректировать `robots.txt` без конфликтов и дублей.

## P1 — производительность и техническая гигиена

1. Устранить блокирующие ресурсы:
   - добавить `defer/async` для проблемных скриптов;
   - проверить, что порядок инициализации JS не сломан.
2. Вынести inline JS/CSS из шаблонов в версионированные ассеты.
3. Провести чистку legacy JS:
   - удалить неиспользуемые плагины;
   - объединить актуальные ресурсы в 1-2 бандла, где возможно.
4. Исправить HTML-дефекты:
   - заменить `<spam>` на `<span>`;
   - убрать пробелы в `href`;
   - устранить невалидные/дублирующиеся атрибуты и ID.
5. Кэш:
   - включить/проверить DB cache в MODX;
   - обеспечить долгий `Cache-Control` для версионированной статики.

## P2 — изображения, LCP/CLS, микроразметка, sitemap

1. Изображения:
   - проставить `width/height` у ключевых изображений (снижение CLS);
   - использовать `loading="lazy"` + `decoding="async"` там, где уместно;
   - для LCP-изображения: `preload`/`fetchpriority="high"`, корректный размер/формат.
2. Микроразметка:
   - унифицировать формат (предпочтительно JSON-LD);
   - валидировать шаблоны `homepage/category/product/article`.
3. `sitemap`:
   - проверить карты сайта;
   - включить главную страницу;
   - актуализировать `lastmod`;
   - убрать нерелевантные URL по списку администратора.

## P3 — наблюдаемость и контроль качества

1. Регламентный Lighthouse (mobile/desktop) до/после изменений.
2. Дашборды Метрики:
   - 404 по паттернам;
   - доля параметрических URL;
   - bot/no-bot.
3. Релизный чеклист:
   - no inline garbage;
   - no malformed href;
   - schema валидна;
   - cache headers корректны.

## 5) Целевые KPI (согласованные, усиленные и реалистичные)

Сверка проводится по `PageSpeed/Lighthouse` на момент сдачи.

- Performance Score: mobile `>= 65-70`, desktop `>= 92`
- FCP: mobile `<= 1.8s`, desktop `<= 0.7s`
- LCP: mobile `<= 4.8s`, desktop `<= 1.8s`
- TBT: mobile `0s` (сохранить), desktop `<= 100ms`
- CLS: mobile `<= 0.25`, desktop `<= 0.08`
- Speed Index: mobile `<= 3.8s`, desktop `<= 1.8s`
- INP: mobile `<= 250ms`, desktop `<= 200ms`
- TTFB: mobile `<= 0.9s`, desktop `<= 0.6s`
- Размер главной: mobile `<= 2.5MB`, desktop `<= 2.0MB`
- HTTP-запросы на главной: mobile `<= 95`, desktop `<= 70`
- Доля 4xx/5xx при обходе ключевых URL: `<= 1%`

## 6) Критерии приемки по каждому этапу

## P0

- URL-паттерны `//` и `index.php?q=` корректно нормализуются (`301`) без циклов.
- Canonical-политика документирована и соблюдается на ключевых типах страниц.
- `robots.txt` не содержит дублирующих и конфликтующих директив.
- Версия `Login Extra` обновлена и подтверждена.

## P1

- Блокирующие скрипты устранены или безопасно отложены.
- В шаблонах нет `<spam>`, пробелов в `href`, явных дублей ID.
- Настроены корректные cache headers для статики.

## P2

- У ключевых изображений есть `width/height`.
- LCP-изображение загружается приоритетно и стабильно.
- JSON-LD валиден на выборке основных шаблонов.
- `sitemap` актуален и включает главную.

## P3

- Получены отчеты Lighthouse до/после.
- Обновлены и переданы ссылки/скриншоты дашбордов Метрики.
- Пройден релизный чеклист.

## 7) Формат отчета от агента Cursor

Агент обязан предоставить:

1. Список фактически измененных файлов и конфигов.
2. Что именно сделано по каждому пункту P0-P3.
3. Что не удалось сделать и почему (блокеры, доступы, зависимости).
4. Таблицу "до/после" по KPI.
5. Список рисков и рекомендации на следующий спринт.
